# 13. SCROLL EXPERIENCE

The scroll should behave like moving through a technical document that gradually becomes more visual.

Use GSAP ScrollTrigger for large scroll sequences where deterministic scroll orchestration is valuable.

Use Motion for React for:

- component-level entrances
- hover interactions
- layout transitions
- small state changes
- gestures

Do not animate every element.

### Motion rule

Every animation must answer at least one of these questions:

- Does it explain structure?
- Does it guide attention?
- Does it communicate state?
- Does it reveal hierarchy?
- Does it improve navigation?

If not, remove it.

GSAP ScrollTrigger is specifically suited to scrub/pin/trigger scroll-driven timelines, while Motion for React is well-suited to component-level and gesture/layout interactions. Use the two systems intentionally rather than duplicating responsibility.

# 30. PERFORMANCE REQUIREMENTS

The website itself is part of the engineering portfolio, so performance is part of the deliverable.

Target excellent Core Web Vitals:

- LCP ≤ 2.5s
- INP ≤ 200ms
- CLS ≤ 0.1

Measure at the 75th percentile when real field data becomes available; during development use Lighthouse / DevTools / WebPageTest as lab tools.

### Performance rules

- Avoid huge hero videos.
- Lazy-load noncritical images.
- Use responsive image sizes.
- Do not ship a large 3D scene on every route.
- Dynamically import heavy WebGL code.
- Keep the main thread clear during initial load.
- Prefer transforms and opacity for animation.
- Avoid layout-triggering animations.
- Avoid hundreds of DOM elements moving independently.
- Use IntersectionObserver or appropriate viewport APIs for lightweight reveals.
- Split code by route/feature.
- Avoid unnecessary animation libraries when CSS is enough.

For Three.js:

- cap device pixel ratio
- reduce geometry/particle counts on small devices
- pause or lower rendering when off-screen
- dynamically import the 3D layer
- provide a non-WebGL fallback
